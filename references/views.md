# Custom Obsidian views

KOB preserves the product `views/` directory for hand-authored Markdown,
Dataview, and Bases content. Use `kob view list --product <product>` to discover
Markdown files stored there. Backboard is the maintained backlog review surface;
custom Obsidian views are optional vault content and are not generated by KOB.

If you want fewer plugin dependencies, consider Obsidian **Bases** for
table-style views. See `references/bases.md`.

## Tree by parent

Use Dataview or DataviewJS to build parent/child views from `parent` fields.
Avoid encoding hierarchy in folders.
Queries should target `_kano/backlog/items` to include all item subfolders.
Hide `Done`/`Dropped` items in views by default (view-level archive).

## Example: List Epic items

```dataview
table id, state, priority, iteration
from "_kano/backlog/items"
where type = "Epic" and state != "Done" and state != "Dropped"
sort created asc
```

## Example: Items by iteration

```dataview
table id, type, state, priority
from "_kano/backlog/items"
where iteration != null and state != "Done" and state != "Dropped"
sort iteration asc, priority asc
```

## Discovery

Store custom Markdown views under the active product's `views/` directory, then
list them without modifying canonical items or view files:

```bash
kob view list --product <product>
```
